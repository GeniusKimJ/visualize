# 안양도시공사 체육시설 반자동 예약 도우미

매주 일요일 예약 오픈을 기다렸다가, 설정한 날짜·시간·코트를 우선순위대로 찾아 **최종 신청 버튼 직전까지** 진행하고 알림을 보냅니다.
**최종 신청 클릭, 비밀번호 입력, 보안문자/본인인증은 사용자가 직접** 합니다.

- 의존성: Python 3.10+ 와 Playwright 하나 (나머지는 표준 라이브러리)
- 브라우저: PC에 설치된 **실제 Chrome** (키보드보안 EasykeyTec 연동 목적)

## 폴더 구조

```
auc_reserve/
├── main.py            # 실행 진입점 (--login/--check/--inspect/--open/--watch)
├── schedule.py        # 오픈 일시·목표 날짜 계산
├── site_selectors.py  # 사이트 셀렉터 (⚠ 추정값, 반드시 확인)
├── notifier.py        # 소리 + 텔레그램 알림
├── timesync.py        # NTP / 서버 시간 보정
├── config.json        # 예약 조건
├── .env.example       # 아이디 (복사해서 .env)
├── run_weekly.bat     # 작업 스케줄러가 실행할 파일
├── register_task.bat  # 작업 스케줄러 등록
└── tests/             # 단위 테스트
```

## 설치 (Windows)

```bat
pip install -r requirements.txt
copy .env.example .env
```

`playwright install`은 하지 않아도 됩니다. 설치된 Chrome을 사용합니다.
`.env`에 아이디만 넣으세요. 비밀번호는 넣지 않습니다.

## 사이트 구조 (2026-10-31 확인, 호계체육관 배드민턴장 `facilityCategoryNo=1`)

- **오픈 규칙(공지):** 이용일 **7일 전 15:00 ~ 1일 전 23:59**, 당일 예약 불가
- **시간표:** 평일 09:00 / 10:40 / 12:20 / 13:55 / 15:30 / 17:10 / 18:50 / 20:30 (각 90분), 일요일 09:00~16:30
- **코트 구분 없음:** `facilities`는 비워 두세요 (`[]`)
- **로그인:** `/sign/in/base/user` (아이디 `#id`, 비밀번호는 EasykeyTec 보호). 안양시 통합 로그인(SSO)도 있음
- **주의:** 일정 시간 동안 이용이 없으면 자동 로그아웃됩니다. 다른 IP에서 같은 계정으로 로그인하면 기존 접속이 끊깁니다.

## ⚠ 처음 한 번: 신청서 셀렉터 맞추기 (필수)

로그인 전 화면(로그인, 달력, 시간표)은 실제 사이트에서 확인했습니다.
**로그인 뒤 화면(신청서 `reservationStep2` 이후)은 아직 추정값**이라 맞춰야 합니다.

1. `python main.py --inspect` 실행
2. 열린 브라우저에서 아래 화면으로 차례로 이동하고, 화면마다 콘솔에서 Enter를 누릅니다.
   - 로그인 페이지 / 로그인 후 메인
   - 예약 달력 (오픈 전 주와 오픈된 주 둘 다)
   - 날짜를 누른 뒤 시간표
   - 신청서 화면 / 최종 확인 화면 (**최종 버튼은 누르지 마세요**)
3. `logs/inspect_*.html`, `.json`, `.png`가 저장됩니다.
   이 파일을 Claude에게 주면서 "site_selectors.py 맞춰줘"라고 하면 됩니다.
4. `python main.py --check`로 각 셀렉터에 걸리는 요소 개수를 확인합니다. 0이면 다시 수정합니다.

주요 항목:

| 상수 | 뜻 |
|---|---|
| `LOGIN_URL`, `LOGIN_ID_INPUT`, `LOGGED_IN_MARKER` | 로그인 페이지, 아이디 칸, 로그인 상태 표시(로그아웃 버튼) |
| `CALENDAR_FIRST_OF_MONTH` | 달력 URL에 그 달 1일을 넣을지, 날짜 그대로 넣을지 |
| `DATE_CELL`, `NOT_OPEN_TEXTS` | 날짜 칸, 오픈 전 표시 문구 → **오픈 여부 판정 기준** |
| `SLOT_ITEM`, `SLOT_CLICK`, `UNAVAILABLE_TEXTS` | 시간표 한 행, 행 안의 신청 버튼, 마감 문구 |
| `APPLICANT_FIELDS`, `AGREE_CHECKBOXES`, `FLOW_NEXT_BUTTONS` | 신청서 입력칸, 동의 체크, 중간 단계 버튼 |
| `FINAL_SUBMIT`, `FINAL_BUTTON_TEXTS`, `FINAL_CONFIRM_KEYWORDS` | 최종 버튼 (감지만 하고 절대 누르지 않음) |
| `COMPLETE_TEXTS` | 예약 완료 문구 |

## config.json

| 키 | 설명 |
|---|---|
| `open_weekday`, `open_time` | 오픈 요일·시각 (공지 확인 후 수정) |
| `target_days` | 다음 주에 예약할 요일. 목록 순서가 우선순위. `times`, `facilities`도 앞쪽이 우선 |
| `extra_dates` | 특정 날짜 추가: `"2026-11-14"` 또는 `{"date": "...", "times": [...], "facilities": [...]}` |
| `skip_dates` | 이번 주는 건너뛸 날짜 |
| `default_times`, `default_facilities` | `extra_dates`에 시간·코트를 안 적었을 때 쓰는 값 |
| `max_per_week` | 주간 최대 예약 건수 |
| `applicant` | 신청서 자동 입력값 (키는 `APPLICANT_FIELDS`와 같아야 함) |
| `notify` | 텔레그램 봇 토큰, chat_id, 소리 사용 여부 |
| `watch_on_fail` | 전부 마감일 때 감시 모드 전환: `ask` / `auto` / `off` |
| `final_wait_min` | 최종 신청을 기다리는 시간(분) |
| `keepalive_min` | 세션 유지 점검 간격(분, 최소 5) |
| `max_wait_after_open_min` | 오픈이 안 될 때 기다리는 최대 시간(분) |

시간은 **시작 시각**으로 적습니다 (예: `"18:50"`). `"20:00"`처럼 범위의 끝 시각을 적으면 걸리지 않습니다.

## 실행 모드

```bat
python main.py --open --dry-run   :: 브라우저 없이 목표 날짜와 일정만 확인
python main.py --login            :: 로그인 테스트
python main.py --check            :: 셀렉터 / 로그인 / 시간 오차 점검
python main.py --open             :: 오픈 대기 → 즉시 예약
python main.py --watch            :: 빈자리 감시 (30초 + 랜덤 0~15초 간격)
```

## --open 동작 순서 (오픈 10:00 기준)

| 시각 | 동작 |
|---|---|
| 09:20 | 시작, 목표 목록을 텔레그램으로 전송, 로그인 확인 (필요하면 알림 → 직접 로그인) |
| 09:30, 09:50 | 로그인 점검 (그 사이에는 10분 간격으로 세션 유지) |
| 09:55 | NTP + 사이트 서버 시간 보정 |
| 09:57 | 로그인 점검, 첫 목표 날짜 달력 열기 |
| 09:59:58 | 1초 간격으로 새로고침하며 오픈 확인 |
| 오픈 감지 | 목표 날짜를 우선순위대로: 슬롯 선택 → 신청서 입력 → 동의 → **최종 버튼 직전 정지 + 알림** |
| 알림 | **사용자가 최종 신청 클릭** → 완료 문구 감지 → 다음 날짜로 진행 |
| 10:03 | 아직 안 열렸으면 5초 간격으로 바꾸고 알림 |
| 끝 | 결과 요약을 텔레그램으로 전송, 남은 건은 감시 모드 전환 여부 확인 |

## 매주 자동 실행

1. `register_task.bat`를 실행하면 매주 일요일 09:20에 `run_weekly.bat`가 실행되도록 등록됩니다. 오픈 시각이 다르면 `/ST`를 고치세요.
2. Windows 설정 → 전원에서 **절전 모드 '안 함'** 으로 바꿉니다. 화면 꺼짐은 괜찮습니다.
3. 작업 스케줄러는 '사용자가 로그온할 때만 실행'(기본값)으로 둡니다. 브라우저 창이 보여야 직접 클릭할 수 있습니다.

## 매주 체크리스트 (토요일)

- [ ] `python main.py --open --dry-run`으로 목표 날짜 확인 (`skip_dates` 수정)
- [ ] `python main.py --check`로 셀렉터 개수가 0이 아닌지 확인
- [ ] 텔레그램 알림 수신 확인
- [ ] 일요일 오픈 시각에 PC 앞에 있기 (최종 클릭은 직접)

## 알아둘 점

- **세션 쿠키:** Chrome을 닫으면 로그인이 풀리는 사이트가 많습니다. 그래서 `--open`은 시작할 때 로그인을 확인하고 브라우저를 계속 띄워 둡니다. `--login`은 테스트용입니다.
- **확인창(confirm):** 자동 단계에서 "예약하시겠습니까?" 같은 확인창이 뜨면 **취소**하고 사용자에게 넘깁니다. 사용자가 최종 버튼을 누른 뒤 뜨는 확인창은 자동으로 '확인'됩니다. 그 클릭이 사용자의 의사이기 때문입니다.
- **새 창 / 인증:** 새 창이 열리거나 보안문자, 본인인증, 대기열이 감지되면 멈추고 알림을 보냅니다. 우회하지 않습니다.
- **오류:** 오류가 나도 브라우저를 닫지 않습니다. 화면에서 직접 이어서 진행하세요. 로그와 스크린샷은 `logs/`에 남습니다.
- 사이트 이용약관을 확인하고, 1인 개인 용도로만 사용하세요.
