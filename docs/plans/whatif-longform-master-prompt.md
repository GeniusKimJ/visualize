# Claude Code 롱폼 "What If" 애니메이션 영상 — 마스터 프롬프트

> 사용법: 빈 폴더에서 Claude Code를 열고, 아래 `---` 사이의 내용을 첫 메시지로 붙여넣습니다.
> `[ ]` 안의 값은 실행 전에 원하는 대로 바꿉니다.

---

## 0. 역할과 목표

너는 이 프로젝트의 **기획자 · 작가 · 과학 검증자 · 아트 디렉터 · 편집자**다.
목표: 오리지널 "What If" 초능력 애니메이션 **3부작 롱폼 시리즈**를 기획하고, 1편을 완성 MP4로 만든다.
사람은 각 단계 끝의 **승인 게이트**에서만 확인한다. 그 사이의 작업은 전부 네가 코드와 스크립트로 처리한다.

### 프로젝트 변수
- `LANG` = [en]          # 영상 언어 (en = 글로벌, ko = 국내)
- `TARGET_LEN` = [8~10분]  # 1편 길이
- `RENDER_MODE` = [code]   # code = Remotion 코드 애니메이션만 / hybrid = 이미지·영상 생성 API + Remotion 편집
- `TTS_PROVIDER` = [미정]   # 승인 게이트 1에서 결정 (API 키는 `.env`에, 커밋 금지)
- `ART_STYLE` = [플랫 2D, 제한 팔레트, 굵은 실루엣, 영화적 조명]
- `ASPECT` = [16:9, 1920x1080, 30fps]

### 절대 규칙
1. **오리지널만 만든다.** 참고한 채널의 캐릭터, 이름, 세계관, 플롯 장치, 대사를 쓰지 않는다.
   참고 영상의 **구조 원리**(아래 4장)만 쓴다.
   금지 소재 예: 시간 정지·반응속도 능력, 빛 깜빡임으로 뇌를 붙잡는 장치, 노크 신호로 구출, 축구 경기장, 비밀 연구소의 번호 매긴 실험체.
2. 실존 인물의 이름이나 얼굴을 캐릭터로 쓰지 않는다. 과학 해설에서 연구자 이름을 인용하는 것은 허용한다.
3. 기존 IP의 캐릭터, 로고, 음악은 쓰지 않는다. 음악과 효과음은 라이선스가 확인된 것만 쓰고, 출처를 `assets/LICENSES.md`에 남긴다.
4. 영상에 나오는 모든 숫자는 공식이나 출처로 검증한다. 검증한 내용은 `story/fact_check.md`에 남긴다.
5. 렌더링 결과가 매번 같도록 `Math.random()` 대신 시드 랜덤(Remotion `random(seed)`)을 쓰고, 애니메이션은 프레임 번호(`useCurrentFrame`)로만 계산한다.
6. 각 단계가 끝나면 **멈추고** 산출물 요약과 승인 질문을 보낸다. 승인 없이 다음 단계로 넘어가지 않는다.

## 1단계 — 주제 발굴과 선정

1. 아래 공식을 만족하는 주제 후보를 **15개** 만든다.
   **"What If + 내 몸·감각·능력 하나 + 커지는 숫자"**
   - 1편은 현실적인 배율(×10)로 시작하고, 2·3편은 감당할 수 없는 극단까지 키운다.
   - 숫자 하나로 설명되는 제목이어야 한다. 예: "What If Your ___ Was 10x ___?"
2. 각 후보를 아래 기준으로 1~5점 채점하고 표로 만든다.
   | 기준 | 설명 |
   |---|---|
   | 즉시 상상 | 제목만 듣고 장면이 떠오르는가 |
   | 숫자 확장성 | 3편까지 숫자를 키울 수 있는가 |
   | 실제 과학 | 마지막 "이거 진짜야?" 해설에 쓸 실제 연구나 현상이 2~3개 있는가 |
   | 대가 | 능력이 커질수록 잃는 것이 분명한가 (이게 3편의 감정 축) |
   | 시각화 | 코드 애니메이션(`RENDER_MODE`)으로 그리기 좋은가 |
   | 차별성 | 기존 유명 What If 영상과 겹치지 않는가 |
3. 상위 3개를 골라 각각 3부작 제목, 한 줄 로그라인, 대가, 과학 소재를 제시한다.
4. 추천 1순위와 그 이유를 적는다.

> 참고 예시 (그대로 쓰지 말고 비교 기준으로만 쓸 것):
> "What If You Could Hear Everything?"
> 청각 ×10 → 벽 너머 심장박동 → 완전한 침묵을 듣는 단계.
> 과학 소재는 칵테일파티 효과, 무향실, 재난 구조 때의 '침묵 시간' 등.

**산출물:** `story/01_topics.md`
**▶ 승인 게이트 1:** 주제 선택, `TTS_PROVIDER`, `RENDER_MODE` 확정

## 2단계 — 시리즈 바이블

`story/02_series_bible.md`에 아래를 쓴다.
- **세계관 규칙 3개.** 능력이 어떻게 작동하고, 무엇이 대가이고, 무엇이 한계인지. 숫자로 정의한다.
- **에스컬레이션 표.** 편별 배율, 대표 숫자, 그 숫자가 화면에서 어떻게 보이는지.
- **캐릭터 4~6명.** 이름(오리지널), 나이, 원하는 것, 두려운 것, 말버릇, 실루엣 특징, 컬러 키.
  - 주인공
  - 일상을 대표하는 절친
  - 능력을 이해하는 멘토
  - "끝까지 가면 이렇게 된다"를 보여주는 선배 사례
  - 주인공의 꿈이나 목표를 대표하는 인물
- **주인공의 꿈.** 능력 덕분에 가능해지는 일상의 목표. 스포츠는 쓰지 않는다. 예: 구조대 시험, 음악 오디션, 등반, 요리 대회.
- **3편 감정 질문.** "능력을 지킬까, ___를 지킬까?" 한 문장.

## 3단계 — 비트 시트 (참고 영상 구조 원리 적용)

각 편마다 `story/03_beats_partN.md`를 쓴다. 기준 길이는 9분이다.

| 시간 | 비트 | 필수 요소 |
|---|---|---|
| 0:00–0:20 | **콜드 오픈** | 클라이맥스 직전 장면 + "대가는 전부"라는 한 줄. 첫 문장은 감각적 이미지로 시작한다 |
| 0:20–0:40 | 규칙 또는 지난 이야기 | 2·3편은 전편 요약. 이 편만 봐도 이해되게 쓴다 |
| 0:40–2:40 | 설정 | 규칙을 숫자로 보여준다. **복선 A, B, C를 심는다** |
| 2:40–4:00 | 일상과 꿈 | 꿈에 다가갈 기회, 절친과의 관계, 대가의 징후 |
| 4:00–5:10 | 위기 | 시간 압박을 숫자로 계산한다 (예: "X초 안에 Y미터") |
| 5:10–6:40 | 클라이맥스 | 선택 → 희생 → **복선을 회수해서 해결**. 갑자기 튀어나온 해결책은 금지 |
| 6:40–8:10 | 결말 | 감정 정리 + 앞에서 나온 소소한 장치(콜백) + 유머 한 번 |
| 8:10–8:50 | **"이거 진짜야?"** | 실제 연구나 현상 2~3개. "부분적으로 진짜"라는 톤 |
| 8:50–끝 | 시청자 행동 유도 | "가능할까?" + **"다음엔 어떤 능력을 다룰까?"** 댓글 질문 |

**복선 규칙**
- 모든 복선은 `story/setups_payoffs.md` 표에 [심은 시간 → 회수 시간 → 화면 표현]으로 기록한다.
- 해결책은 1편이나 이 편 앞부분에서 이미 보여준 것으로만 만든다.
- 회수 장면이 최소 3개, 웃음을 주는 콜백이 최소 1개 있어야 한다.

## 4단계 — 대본

`story/04_script_partN.md`

- **내레이션은 2인칭 "You"로 쓴다.** ("Your name is ___.") 시청자를 주인공 자리에 앉힌다.
- 문장은 짧게. 한 줄에 12단어 이내로 쓰고, 말줄임표("...")로 리듬을 만든다.
- 대사는 캐릭터 말버릇을 반영하고, 한 번에 2문장 이내로 쓴다.
- 장면마다 `[SFX]`, `[MUSIC]`, `[VISUAL]` 메모를 단다.
- 분량 기준: 영어 기준 분당 약 130~150단어.
- 다 쓰고 나서 **숫자 검증표**를 만든다 (`story/fact_check.md`).
  | 대사 속 숫자 | 공식이나 근거 | 계산값 | 출처 | 통과 여부 |
  예: 자유낙하 시간은 t = √(2h/g), 소리 속도는 343 m/s (20°C 공기 기준).

**▶ 승인 게이트 2:** 바이블, 비트 시트, 1편 대본, 검증표

## 5단계 — 샷 리스트 (`scenes/partN.json`)

대본을 3~6초 단위의 컷으로 나눈다. 9분이면 약 100~150컷이다.

```json
{
  "id": "p1_s012",
  "beat": "setup",
  "start_hint": "01:12",
  "duration_s": 4.5,
  "narration": "…",
  "dialogue": [{"char": "MENTOR", "line": "…"}],
  "visual": {
    "location": "rooftop_night",
    "characters": ["HERO", "MENTOR"],
    "action": "…",
    "camera": "slow push-in | wide | close-up | over-shoulder",
    "fx": ["rain_particles", "number_overlay:0.025s"]
  },
  "sfx": ["distant_thunder"],
  "music": "tension_low",
  "setup_payoff": "SETUP_B"
}
```

- 숫자가 화면에 뜨는 컷(`number_overlay`)은 최소 8개 넣는다. 이 장르의 핵심 시각 언어다.
- 3~4컷마다 카메라 종류를 바꾼다.

## 6단계 — 비주얼 제작

### `RENDER_MODE = code` (기본)
- **Remotion (React → MP4)** 으로 만든다.
- 캐릭터는 SVG 파츠(머리, 몸, 팔, 표정)를 조합하는 리그로 만든다. `src/characters/<Name>.tsx`
- 배경은 레이어(원경, 중경, 근경)로 나눠 패럴랙스를 준다. `src/locations/*.tsx`
- 효과는 재사용 컴포넌트로 만든다: 비, 파티클, 화면 정지, 숫자 오버레이, 비네팅, 필름 그레인.
- 장면 컴포넌트는 `scenes/partN.json`을 읽어서 자동으로 배치한다. 수작업으로 이어붙이지 않는다.
- 팔레트와 폰트는 `src/style/tokens.ts` 한 곳에서 관리한다.

### `RENDER_MODE = hybrid`
- `scripts/gen_images.py`: 캐릭터 기준 시트(정면, 측면, 표정 6종)를 먼저 확정하고, 모든 장면에 같은 기준 이미지를 넣어 생성한다.
- `scripts/gen_clips.py`: 이미지를 3~5초 클립으로 만든다. 실패하면 3회까지 다시 생성한다.
- 모든 프롬프트, 시드, 결과 파일 경로를 `assets/manifest.json`에 기록한다.
- 클립은 Remotion에서 자막, 숫자 오버레이, 전환 효과와 합성한다.

**▶ 승인 게이트 3:** 캐릭터 시트, 로케이션 3곳, 30초 테스트 렌더

---

## 7단계 — 오디오

- `scripts/gen_voice.py`: 내레이터 1명 + 캐릭터별 목소리로 문장 단위 WAV를 만들고, 길이를 `audio/timing.json`에 저장한다.
- **컷 길이는 음성 길이를 기준으로** 자동 조정한다 (`duration_s = max(음성 길이 + 0.3초, 최소 2초)`).
- 효과음과 음악은 라이선스가 확인된 것만 쓴다.
- 믹싱 기준: 내레이션 −16 LUFS, 음악은 내레이션 아래로 −12dB 덕킹.
- 자막은 대본과 타이밍으로 `out/partN.srt`를 자동 생성한다.

---

## 8단계 — 조립과 렌더

- `npx remotion render`로 렌더링하고 `ffmpeg`로 오디오를 합친다.
  출력: `out/partN_final.mp4` (H.264, 1080p30, AAC 48kHz)
- `scripts/qa.py`로 자동 검수한다.
  - [ ] 전체 길이가 `TARGET_LEN` 안에 드는가
  - [ ] 검은 프레임이나 빈 프레임이 0.5초 넘게 이어지는 곳이 없는가
  - [ ] 자막과 음성 타이밍 오차가 0.2초 이하인가
  - [ ] 라우드니스가 −14~−16 LUFS인가
  - [ ] 모든 복선이 회수되었는가 (`setups_payoffs.md`)
  - [ ] 첫 20초 안에 콜드 오픈 훅과 대가 한 줄이 있는가
  - [ ] 숫자 오버레이가 8개 이상인가
- QA 결과를 `out/qa_report.md`로 남긴다.

**▶ 승인 게이트 4:** 최종 MP4 + QA 리포트

---

## 9단계 — 업로드 패키지 (`publish/partN/`)

- **제목 10개.** "What If ___?" 형식, 50자 이내, 숫자 포함 우선. A/B 추천 2개를 고른다.
- **썸네일 3안.** 큰 숫자 하나 + 감정이 드러난 얼굴 + 3단어 이하 텍스트. Remotion `Still`로 1280x720을 렌더링한다.
- **설명란.**
  - 첫 2줄 훅
  - 시리즈 링크
  - "이 편만 봐도 된다"는 안내
  - **챕터 타임스탬프** (비트 시트 기준)
  - 과학 해설 요약
  - 댓글 질문
  - 해시태그 3~5개
- **고정 댓글.** "다음 능력 투표" 질문.
- **AI 사용 표시 메모.** 실제처럼 보이는 합성 장면이 있으면 업로드할 때 변경·합성 콘텐츠 표시를 켠다.

## 프로젝트 구조

```
whatif-series/
├── CLAUDE.md                  # 이 프롬프트의 규칙 요약 + 스타일 토큰 + 금지사항 (항상 로드됨)
├── .env.example               # TTS_API_KEY=, IMAGE_API_KEY= (실제 .env는 .gitignore)
├── .claude/
│   └── commands/              # 단계별 슬래시 커맨드
│       ├── topics.md          # /topics  → 1단계
│       ├── bible.md           # /bible   → 2단계
│       ├── beats.md           # /beats N → 3단계
│       ├── script.md          # /script N → 4단계 + 숫자 검증
│       ├── shots.md           # /shots N → 5단계
│       ├── render.md          # /render N → 6~8단계
│       └── publish.md         # /publish N → 9단계
├── story/
│   ├── 01_topics.md
│   ├── 02_series_bible.md
│   ├── 03_beats_part{1,2,3}.md
│   ├── 04_script_part{1,2,3}.md
│   ├── setups_payoffs.md
│   └── fact_check.md
├── scenes/
│   └── part{1,2,3}.json
├── src/                       # Remotion 프로젝트
│   ├── Root.tsx
│   ├── Episode.tsx            # scenes JSON → 시퀀스 자동 배치
│   ├── characters/
│   ├── locations/
│   ├── fx/                    # Rain, Particles, Freeze, NumberOverlay, Grain
│   └── style/tokens.ts
├── scripts/
│   ├── gen_voice.py
│   ├── gen_images.py          # hybrid 모드 전용
│   ├── gen_clips.py           # hybrid 모드 전용
│   ├── build_srt.py
│   ├── mix_audio.sh
│   └── qa.py
├── assets/
│   ├── audio/{voice,sfx,music}/
│   ├── images/
│   ├── manifest.json
│   └── LICENSES.md
├── out/
└── publish/
```

## 시작 지시

1. 위 구조로 폴더를 만들고, `CLAUDE.md`와 `.claude/commands/*.md`부터 작성해라.
2. Remotion 프로젝트를 초기화하고, 10초짜리 "Hello" 테스트 렌더로 렌더링 환경을 확인해라.
3. 그다음 **1단계**를 진행하고, 승인 게이트 1에서 멈춰라.
